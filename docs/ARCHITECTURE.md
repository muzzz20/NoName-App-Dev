# ARCHITECTURE — Strayfriends

> Canonical technical reference for the **completed** Strayfriends app
> (v1.0.0). This is ground truth for how the code is wired — read it
> before changing data shapes, routes, security rules, or money handling.
> For UI tokens see `DESIGN.md`; for deploy steps see `DEPLOYMENT.md`;
> for the security posture see `SECURITY_REVIEW.md`.

## 1. Stack at a glance

| Layer | Choice | Notes |
|---|---|---|
| Client | Flutter (Dart SDK `^3.11.4`) | Android · iOS · Web from one codebase |
| Navigation | `go_router` ^17 | Declarative routes + auth redirect guard |
| State | **None** (no Provider/Riverpod/Bloc) | `StatefulWidget` + service classes + `StreamBuilder` |
| Auth | `firebase_auth` | Email/password only |
| Database | `cloud_firestore` | 7 collections (see §4) |
| Files | `firebase_storage` | Report/campaign images. **Supabase was removed** |
| Server logic | Cloud Functions (Node.js, `functions/`) | Aggregation, invariants, Stripe, FCM |
| Payments | **Stripe Checkout (test mode)** | Redirect flow; no key on client |
| Push | `firebase_messaging` (FCM) | Topic `new-activities`; web push not yet activated |
| Maps | `flutter_map` + `latlong2` + OSM tiles | `geolocator` for current location |
| Media | `image_picker` + `image` | Client-side resize before upload |
| Fonts | `google_fonts` (Inter) | See `DESIGN.md` |

The app boots on a fresh clone with **zero local config** — Firebase
config is compiled into `lib/firebase_options.dart` (committed). No `.env`
is required to run the client.

## 2. Project layout (`lib/`)

Feature-first. Each feature owns its `models/`, `screens/`, `services/`
(and `widgets/` where it has reusable UI). Cross-feature plumbing lives
in `core/`.

```
lib/
├── main.dart                  # Firebase init → NotificationService.init() → runApp
├── firebase_options.dart      # generated by flutterfire configure (committed)
├── core/
│   ├── notifications/notification_service.dart   # FCM init, token, deep-link taps
│   ├── router/app_router.dart                    # go_router + AppRoutes + auth guard
│   └── theme/                                    # app_colors · app_text · app_spacing · app_theme
└── features/
    ├── auth/         models(user_profile) · screens(login,register,splash,profile) · services(auth_service)
    ├── reporting/    models(cat_report) · screens(feed,submit,detail,my_reports,success) · services(reports,photo_upload,location) · widgets(report_card,map_picker,static_map,condition_badge)
    ├── fundraising/  models(campaign,donation,allocation) · screens(list,detail,donation_flow,my_donations,receipt,admin_manage) · services(campaigns,donations,allocations,payment,transparency)
    ├── volunteer/    models(activity,signup) · screens(list,detail,my_activities,admin_manage) · services(activities,signups)
    ├── dashboard/    screens(stakeholder_dashboard,public_stats) · services(dashboard)
    └── help/         screens(help)
```

## 3. App wiring & state management

**There is no state-management library.** The pattern, everywhere, is:

1. A screen is a `StatefulWidget`.
2. It instantiates the service class it needs directly (e.g.
   `final _reports = ReportsService();`) — no DI container, no provider.
3. Live data comes from `StreamBuilder` over Firestore `.snapshots()`.
4. Auth state comes from `FirebaseAuth.instance.authStateChanges()` /
   `currentUser`.

`main.dart` does three things: `Firebase.initializeApp()`, then the
defensive `NotificationService.init()` (wrapped so a push failure never
blocks startup), then `runApp(StrayfriendsApp())`. The app is
`MaterialApp.router` with `theme: AppTheme.light` and the router from
`buildAppRouter()`.

> When adding a feature, **follow this pattern** — instantiate the
> service in the screen and stream from Firestore. Don't introduce a
> state-management package without a deliberate decision.

## 4. Data model — Firestore collections

Seven collections. **All money is stored as integer sen** (1 RM = 100
sen) to avoid floating-point rounding — see §6. Firestore field names are
plain (`amount`, `goalAmount`, `currentAmount`); the Dart models expose
them with a `Sen` suffix (`amountSen`, `goalAmountSen`, `currentAmountSen`).
The doc ID is never duplicated as a field inside the doc.

| Collection | Doc ID | Model | Written by | Read access |
|---|---|---|---|---|
| `users` | Firebase UID | `UserProfile` | self (role locked to `user`) | any signed-in |
| `reports` | auto | `CatReport` | any signed-in (own `userId`, status `pending`) | **public** |
| `campaigns` | auto | `Campaign` | admin/ngo create+update; `currentAmount` by Cloud Function | **public** |
| `donations` | auto | `Donation` | **`stripeWebhook` Cloud Function only** — client create = `if false` | donor (own) + admin/ngo |
| `allocations` | auto | `Allocation` | admin/ngo (subject to server invariant) | **public** |
| `activities` | auto | `Activity` | admin/ngo create; `slotsRemaining` ±1 by any signed-in | **public** |
| `signups` | `{activityId}_{volunteerId}` | `Signup` | signed-in (own); deletable by owner | volunteer (own) + admin/ngo |

### Enums (stored lowercase via `storageKey == name`)
- `CatCondition`: healthy · injured · sick
- `ReportStatus`: pending → inProgress → resolved / rejected (admin transitions)
- `CampaignStatus`: active · completed · archived
- `DonationStatus`: success · failed (failed donations are recorded for audit, contribute nothing)
- `ActivityStatus`: upcoming · completed · cancelled

### Denormalized fields (avoid joins)
- `donations.donorName` ← copied from `users/{uid}.fullName` at write time
- `signups.volunteerName` ← copied from profile at sign-up

### Composite indexes (`firestore.indexes.json`)
Per-collection `(ownerField ASC, sort DESC/ASC)` pairs back the "my X"
and admin-management queries (e.g. `reports` by `userId`+`createdAt`,
`campaigns`/`activities` by `createdBy`, `donations` by `donorId`/`campaignId`).
Adding a `where`+`orderBy` on a new field pair means adding an index here.

## 5. Routing & the visitor (public) model

`go_router`, configured in `core/router/app_router.dart`. Route strings
are constants on `AppRoutes`. `buildAppRouter()` installs a `redirect`
guard refreshed by auth state (`GoRouterRefreshStream`).

**Three redirect rules:**
1. `/` (splash) → always `/home`.
2. Signed-in user at `/login` or `/register` → `/home`.
3. **Not** signed-in, at a non-auth, non-public route → `/login`.

`_isPublicRoute()` is the visitor whitelist — what an unauthenticated
visitor may view:

| Public (visitor OK) | Auth-required |
|---|---|
| `/home` (feed) | `/profile`, `/my-reports`, `/my-donations`, `/my-activities` |
| `/campaigns`, `/campaign/:id` | `/report/new`, `/report/success` |
| `/activities`, `/activity/:id` | `/donate/:id`, `/receipt` |
| `/report/:id` (detail) | `/admin-campaign`, `/admin-activity` |
| `/public-stats`, `/help` | `/dashboard` |

Auth-only **actions** on public screens (donate, sign up, submit report)
prompt sign-in rather than hiding the screen. Firestore read rules
(§7) permit public read of exactly the public routes' data — no write
path is opened to visitors.

## 6. Money: always sen

Every monetary amount — donation, campaign goal/current, allocation — is
an **integer number of sen** (1 RM = 100 sen). Reasons: no float
rounding, and Stripe's `unit_amount` is already in the minor unit.

- Firestore field: `amount` / `goalAmount` / `currentAmount` (integers).
- Dart property: `amountSen` / `goalAmountSen` / `currentAmountSen`.
- UI formats for display only (`RM X.YY`); never store a float.
- Minimum donation enforced at **500 sen (RM 5.00)** in both
  `PaymentService` and the `createCheckoutSession` Cloud Function.

If you add a money field, name it `*Sen`, store an int, and convert at
the display edge.

## 7. Security model (`firestore.rules` + `storage.rules`)

Helpers: `isSignedIn()`, `isSelf(uid)`, `isAdminOrNgo()` (reads
`users/{uid}.role`). Default-deny on any unmatched collection.

Per-collection summary:

- **users** — read: any signed-in; create: self only, `role == 'user'`;
  update: self, **role cannot change**; delete: never.
- **reports** — read: public; create: signed-in, own `userId`, status
  `pending`; update/delete: admin/ngo.
- **campaigns** — read: public; create: admin/ngo, own `createdBy`,
  `currentAmount == 0`, status `active`; update: admin/ngo; delete: never
  (use `archived`). `currentAmount` is bumped by a Cloud Function via the
  service account (bypasses rules).
- **donations** — read: donor (own) or admin/ngo; **create/update/delete:
  `if false`**. Only `stripeWebhook` writes them.
- **allocations** — read: public; create: admin/ngo, own `createdBy`,
  `amount > 0`, campaign must exist; update: admin/ngo; delete: never.
- **activities** — read: public; create: admin/ngo, own `createdBy`,
  `slotsRemaining == slots`, status `upcoming`; update: admin/ngo on any
  field, **OR any signed-in user changing ONLY `slotsRemaining` by ±1**
  (sign-up / cancel); delete: never (use `cancelled`).
- **signups** — read: volunteer (own) or admin/ngo; create: signed-in,
  own `volunteerId`, activity must exist; update: never; delete: owner.

**Storage** (`storage.rules`): public read; authenticated, image-only
write < 5 MB. Role gating is at the Firestore doc level — an orphan
upload is harmless.

## 8. Cloud Functions (`functions/index.js`, Node.js)

Region `asia-southeast1`. Secrets `STRIPE_SECRET` + `STRIPE_WEBHOOK_SECRET`
live in Google Secret Manager (never in repo/client). Deploy:
`firebase deploy --only functions`.

| Function | Trigger | Does |
|---|---|---|
| `onDonationCreate` | `donations/{id}` create | If `status == success`, atomically increments `campaigns.currentAmount`; auto-flips campaign to `completed` when goal crossed. Never rethrows (would double-count on retry). |
| `onAllocationCreate` | `allocations/{id}` create | Enforces invariant **`sum(allocations.amount) ≤ campaign.goalAmount`** in a transaction; rolls back (deletes) the allocation if violated. Rules can't sum cross-doc, so it's enforced here. |
| `createCheckoutSession` | onCall (callable) | Auth + validation, confirms campaign is `active`, creates a Stripe Checkout session, returns `{url, sessionId}`. Min 500 sen. |
| `stripeWebhook` | onRequest (HTTP) | Verifies Stripe signature; on `checkout.session.completed` writes the `donations/{id}` doc (status `success`). Idempotent on `stripeSessionId`. Returns 5xx to let Stripe retry on write failure. |
| `onActivityCreate` | `activities/{id}` create | Publishes an FCM push to topic `new-activities` with deep-link `data.route = /activity/{id}`. Non-fatal. |

**Donation flow end-to-end:** client → `PaymentService.startCheckout` →
`createCheckoutSession` → redirect to Stripe → user pays → `stripeWebhook`
writes the donation → `onDonationCreate` updates the campaign total →
receipt screen streams the donation by `stripeSessionId` until it lands.

## 9. Notifications (FCM)

`core/notifications/notification_service.dart`. `init()` is fully
defensive (try/catch; app boots without push if anything fails):
requests permission, subscribes to topic `new-activities`, saves the FCM
token to `users/{uid}.fcmToken`, and wires tap handling. A tap reads
`data.route` from the message and calls `NotificationService.onNavigate`,
which `main.dart` binds to `_router.go(route)` — so a push deep-links
into `/activity/:id`.

**Web push is not yet activated** (needs a VAPID key + service worker
wiring). Server-side topic publishing already works for mobile.

## 10. Auth & roles

Three roles in `users/{uid}.role`:

| Role | Who | Can |
|---|---|---|
| `user` | Registered student/donor/volunteer (default) | Submit reports, donate, sign up, view all public data |
| `admin` | UTM staff coordinating welfare | + create/manage campaigns, allocations, activities; moderate reports |
| `ngo` | Registered partner (e.g. PAWS Johor) | Same privileges as `admin` |

Role is **locked to `user` on registration**. Admin/NGO are seeded
manually by the lead dev via the Firestore console (`users/{uid}` → set
`role`). There is no in-app self-promotion path — by design.
